# Current state

- **Project status:** Telegram-only MVP published to Cloudflare Pages at `https://iu5hub.pages.dev`, configured in BotFather and successfully opened from Telegram. CI verification, выключенный по умолчанию Cloud.ru deploy job и выключенный по умолчанию Cloudflare Pages deploy job remain in Git as optional automation paths.
- **Current milestone:** private analytics: Cloudflare Worker + D1, verified Telegram identity, protected admin dashboard and `/stats`; existing catalogue, Cloudflare Pages hosting and Yandex Disk integration remain intact.
- **UI QA:** local Playwright 1.63 critical suite uses a Vite `webServer`, deterministic Telegram WebApp and Yandex Disk fixtures, Chromium/iPhone-like Chromium plus local WebKit. GitHub Actions runs Chromium after the existing lint/typecheck/unit/build gate; browser failure artifacts are retained. The browser fixture is test-only and does not alter Mini App security or production data.
- **Completed:** React/Vite SPA, routing, статический `MaterialsRepository`, responsive UI, CI, unit tests и локальный browser smoke test. `npm run dev:telegram` создаёт development-only Quick Tunnel к loopback Vite с HTTP/2; это подготовленный local test path, а не подтверждённый Telegram WebView test или production deployment.
- **In progress:** замена остальных demo-ссылок реальными каталогами Яндекс.Диска. Первый курс уже подключён к публичной папке; третий курс сохранён в интерфейсе без URL, пока материалы готовятся.

- **Known blockers:** публичные каталоги для 3-го и остальных неподключённых курсов. GitHub App имеет доступ только к `gregkorneev/iu5hub`, но Git-import workflow ещё не связал репозиторий с Pages project; GitHub Actions deploy остаётся выключенным без Cloudflare API secrets. Ни один secret не должен попадать в Git или frontend bundle.
- **Important architecture facts:** один статически собираемый React/TypeScript/Vite frontend существует только внутри Telegram Mini App; UI зависит от `MaterialsRepository` и централизованного Telegram integration layer; Cloudflare Pages — technical host; тяжёлые файлы остаются на Яндекс.Диске. Private analytics is a narrow Worker/D1 exception: it validates `initData`, derives a server-keyed pseudonym, stores minimal events and supplies protected `/stats`; see `analytics.md` and `security.md`.
- **Team workflow:** постоянная небольшая команда; новые роли создаются только для действительно новой специализации, а обычные задачи направляются существующим агентам.
- **Last significant change:** 2026-09-21 — исправлен порядок загрузки Telegram SDK: `Telegram.WebApp.ready()` теперь вызывается до показа UI, поэтому системный loader Telegram закрывается. Главная страница оставляет только поиск и каталог курсов; блок «Последние материалы» удалён. Поиск больше не использует demo-каталог: рекурсивно ищет реальные папки и файлы в подключённых публичных каталогах Яндекс.Диска, открывает папку внутри Mini App, а файл — запускает скачивание. Поисковый ввод показывает до пяти живых подсказок после двух символов; Unicode NFC-нормализация исправляет поиск имён с декомпозированными символами (включая «Математический анализ»), а 10-секундный тайм-аут и изоляция ошибок отдельной папки исключают бесконечное ожидание. Вёрстка проверена на ширинах 320, 390, 768 и 1440 px: нет горизонтального переполнения, зоны нажатия в шапке и breadcrumb приведены к 44 px. 4-й курс скрыт, 1-й подключён к публичной папке Яндекс.Диска, 3-й оставлен без URL до готовности материалов. Для файлов из живого каталога убран `Telegram.WebApp.openLink`: кнопка файла и иконка скачивания используют обычную загрузку, чтобы обходить 403 в Telegram external viewer. Production build напрямую загружен в Cloudflare Pages project `iu5hub`; Mini App проверен в Telegram. Поддержка/relay удалены из текущей схемы; локальные процессы проекта остановлены.
- **Last UI QA change:** 2026-09-21 — устранены критическая ARIA-ошибка search suggestions, отсутствие `h1` на главной, race при быстром переходе между папками, stale download error после перехода в другой каталог и clipping подсказки поиска под каталогом на iPhone. Public course 1 and 2 are connected; course 3 intentionally has no URL.
- **Deployment policy:** `deploy-cloudru` и `deploy-cloudflare-pages` запускаются только после `verify`, только для push в `main` и только при соответствующем literal enable variable; оба публикуют только статический Mini App. Cloud.ru job генерирует `error.html`, cache-ит hashed `assets/` как immutable, sync-ит остальные root files с no-cache и публикует `index.html` последним с no-store. Технический host URL не распространяется студентам; Bot/Mini App URL остаётся пользовательским входом.
- **Local Telegram development:** для временного ручного теста использовать `npm run dev:telegram` и `@iu5_archive_bot` только как designated dev-test bot. URL Quick Tunnel меняется с каждым запуском, не хранится в Git и не подтверждает настройку бота, пока реальный запуск не проверен.
