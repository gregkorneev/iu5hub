# Подготовка ручных метаданных поиска

## Поток данных

```text
Публичный Яндекс.Диск
        ↓ npm run search:sync (ручная сеть)
search-tags.csv + search-synonyms.csv (CSV source of truth)
        ↓ npm run search:workbook
Excel tagging-queue.xlsx (листы «Разметка», «Синонимы», «Инструкция»)
        ↓ ручное заполнение
npm run search:workbook:apply
        ↓ импорт ручных полей в CSV
npm run search:validate
        ↓ npm run search:build
src/generated/search-index.json
        ↓
npm run search:coverage
```

`search:sync` обходит публичные каталоги, заданные в конфигурации курсов. Курс без корректной публичной ссылки пропускается. Sync обновляет машинные поля и сохраняет заполненные вручную данные по совпавшему `object_key`; исчезнувшие объекты остаются в таблице с `source_status=missing`, чтобы метаданные не терялись. Переименование или перенос может изменить ключ, если публичный API не даёт пригодного стабильного идентификатора. В таком случае старые метаданные сохраняются как missing, а новый объект появляется отдельной строкой; предупреждение о возможном совпадении не переносит метаданные автоматически.

## Таблицы

Рекомендуемый способ ручной настройки — Excel-книга `data/search/tagging-queue.xlsx`. Команда `npm run search:workbook` обновляет очередь, создаёт книгу и автоматически открывает её в Excel на macOS. Главный лист «Разметка» содержит только папки предметов, лежащие непосредственно внутри семестров (глубина 2; сейчас 29 строк), и два редактируемых поля: «Теги» и «Преподаватель». В «Теги» можно вписывать другие названия, темы и любые важные слова через `;`; имя папки туда добавляется автоматически. В «Преподаватель» указываются имена преподавателей, также через `;`. Эти значения сохраняются как собственные поисковые метаданные папки и учитываются для её содержимого при включённом наследовании. На листе «Синонимы» редактируются глобальные соответствия; лист «Инструкция» объясняет работу. `object_key` и остальные машинные данные скрыты; импорт сопоставляет строки по ключу, а не по позиции. После сохранения запустите `npm run search:workbook:apply`, чтобы перенести теги в CSV, проверить таблицы, собрать индекс и coverage.

CSV (`search-tags.csv`, `search-synonyms.csv`) остаётся source of truth. Workbook — временная рабочая форма, исключена из Git. Для расширенного ручного процесса без Excel используйте `npm run search:tagging-queue` → правка `tagging-queue.csv` → `npm run search:apply-tags`; синонимы можно редактировать напрямую в CSV.

Основной файл для владельца — `data/search/search-tags.csv`. Откройте его в Numbers, Excel, LibreOffice или импортируйте в Google Sheets. Редактируйте только `aliases`, `keywords`, `priority`, `enabled`, `inherit` и `notes`. В списках используйте `;` как разделитель, например `матан; мат анализ`. Пустые поля допустимы; новая строка по умолчанию включена с приоритетом 0.

Для разметки папок используйте `npm run search:tagging-queue`: команда формирует `data/search/tagging-queue.csv` из активных включённых папок, лежащих непосредственно внутри семестров (глубина 2: курс/семестр/папка предмета; сейчас 29 строк). Папки самих семестров и вложенные разделы в приоритетный список не попадают. Флаг `npm run search:tagging-queue -- --all` включает все активные включённые папки. `status`: `root` — глубина 0, `priority` — глубина 2, `later` — остальные уровни. Очередь содержит машинные поля `object_key`, `course_id`, `course_title`, `type`, `path`, `name`, `depth`, `status`, `source_status`; не меняйте их. Редактируйте только `aliases`, `keywords`, `inherit`, `priority`, `enabled` и `notes`, затем запустите `npm run search:apply-tags`. Команда проверяет машинные поля против основной таблицы и меняет только ручные значения; при несовпадении остановится. Основная таблица `search-tags.csv` остаётся source of truth.

`inherit=TRUE` у включённой папки означает, что будущий индекс добавит её теги как отдельные унаследованные совпадения у вложенных объектов. Собственные aliases/keywords объекта сохраняются одновременно с унаследованными. Индекс хранит ссылки на источники с расстоянием и `objectKey`; более близкий родитель имеет преимущество над дальним при ранжировании унаследованных совпадений. Отключённая папка не включается в индекс и не передаёт собственные теги; включённый потомок может независимо унаследовать теги других включённых предков выше по пути. Файлы по умолчанию имеют `inherit=FALSE`. Это не меняет production search.

`data/search/search-synonyms.csv` предназначен для глобальных соответствий, не привязанных к отдельной папке. Production-поиск папок использует только пользовательские «Теги» (поле `keywords`) и «Преподаватель». Эти поля равноправны: совпадение по любому из них ведёт к папке; пустые значения не индексируются.

Подсказки появляются сразу с первого символа. Сопоставление идёт по началу тега или имени преподавателя без учёта регистра (`Мат`, `мат`, `МАТ` работают одинаково) и с нормализацией Unicode. Нажатие открывает папку внутри каталога курса. Полный поиск и live suggestions используют одну функцию и один локальный индекс. Поиск не сканирует Yandex API, filenames, paths, aliases или global synonyms; название папки находится только потому, что записано в её список тегов. Содержимое выбранной папки по-прежнему загружается из Яндекс.Диска после перехода.

## Команды

- `npm run search:sync` — получить актуальный каталог; требует доступа к сети и запускается вручную.
- `npm run search:workbook` — обновить очередь, создать Excel-книгу и открыть её в Excel на macOS.
- `npm run search:workbook:apply` — импортировать ручные поля и синонимы из книги в CSV, проверить, собрать индекс и coverage.
- `npm run search:validate` — проверить CSV и соответствие строк локальному снимку каталога.
- `npm run search:build` — собрать machine-readable индекс из таблиц и каталога; сеть не нужна.
- `npm run search:build:check` — проверить, что закоммиченный индекс совпадает с результатом сборки; сеть не нужна.
- `npm run search:coverage` — показать заполненность и наиболее важные незаполненные папки.
- `npm run search:tagging-queue` — создать очередь папок предметов непосредственно внутри семестров (глубина 2).
- `npm run search:tagging-queue -- --all` — включить в очередь все активные включённые папки.
- `npm run search:tagging-queue:check` — проверить в CI, что закоммиченная очередь актуальна; сеть не нужна.
- `npm run search:apply-tags` — применить ручные поля очереди к основной таблице после сверки machine fields.
- `npm run search:prepare` — последовательно выполнить sync, обновить очередь, validate, build и coverage.

CI запускает validate и build check по закоммиченным данным и не обращается к API Яндекс.Диска. `search:sync` в CI не запускается.

## Индекс и будущая схема

`src/generated/search-index.json` — полный сгенерированный metadata-артефакт; `src/generated/search-folder-index.json` — компактный production-индекс только активных папок с тегами, содержащий «Теги» и «Преподаватель». **DO NOT EDIT GENERATED SEARCH INDEX MANUALLY.** Пересоберите оба файла командой `npm run search:build` после правок таблиц.

При будущем переносе в Cloudflare D1 таблица объектов соответствует структуре:

```text
search_metadata
---------------
object_key, course_id, type, path, name,
aliases, keywords, priority, enabled, inherit, notes, source_status
```

Глобальные синонимы хранятся отдельно, например в `search_synonyms(term, synonyms, enabled, notes)`. Для унаследованных совпадений индекс хранит ссылки на родительские объекты и расстояние, а не дублирует теги в каждой строке. D1 для поисковых метаданных сейчас не создаётся.

Текущий production search ограничен префиксными совпадениями по тегам и преподавателям; эти поля имеют одинаковый приоритет. Наследование и `priority` пока не участвуют в tag-only поиске. Если позже появится более сложное ранжирование, live suggestions и полный поиск должны продолжать использовать один индекс и один scoring engine.

Подробная инструкция по редактированию находится в [data/search/README.md](../data/search/README.md).
