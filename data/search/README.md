# Таблица тегов поиска

## Быстрый порядок работы в Excel

1. Запустите `npm run search:workbook` и откройте `data/search/tagging-queue.xlsx`.
2. На листе «Разметка» найдите папку и впишите важные слова в «Теги», преподавателя — в «Преподаватель».
3. При необходимости задайте общие синонимы на листе «Синонимы». Лист «Инструкция» кратко описывает поля.
4. Сохраните книгу и запустите `npm run search:workbook:apply`.
5. Команда импортирует поля в CSV, проверит данные, соберёт индекс и покажет coverage.

Теги можно перечислять через `;`. CSV-файлы `search-tags.csv` и `search-synonyms.csv` остаются source of truth. Excel-книга — временная рабочая форма и не хранится в Git.

Production-поиск использует только поля «Теги» и «Преподаватель»: подсказки появляются с первой буквы, поиск идёт по началу слова без учёта регистра и открывает выбранную папку. Оба поля равноправны. Пустые поля не создают совпадений; имена файлов на Яндекс.Диске не сканируются.

В обычной работе CSV открывать не требуется: редактируйте данные в Excel-книге и применяйте через `search:workbook:apply`. `search-tags.csv` — исходная таблица, в которой одна строка соответствует папке или файлу подключённого публичного каталога Яндекс.Диска; прямое редактирование CSV — расширенный вариант ниже.

Основной лист Excel предельно простой: одна строка на папку и два синих поля — «Теги» и «Преподаватель». В «Теги» вписывайте любые слова, которые помогут найти папку или её содержимое: другие названия, темы и важные слова. Название самой папки уже добавляется автоматически. В «Преподаватель» можно указать одного или нескольких преподавателей. Несколько значений разделяйте `;`. Приоритет, включение, наследование и заметки сохраняются в CSV и для обычной разметки не требуют заполнения.

## Если вы редактируете CSV напрямую

Редактируйте только эти столбцы:

- `aliases` — другие названия объекта;
- `keywords` — темы и слова, по которым объект нужно находить;
- `priority` — целое неотрицательное число для ручного повышения результата; обычно `0`, важным объектам можно поставить `10`, `20` и выше;
- `enabled` — `TRUE` или `FALSE`; `FALSE` исключает объект из будущего поиска;
- `inherit` — `TRUE` или `FALSE`; у папки `TRUE` добавляет её теги как отдельные унаследованные совпадения для вложенных объектов. Собственные теги объекта при этом остаются и учитываются вместе с унаследованными. У файлов по умолчанию `FALSE`;
- `notes` — заметка владельца, не влияющая на поиск.

В `aliases` и `keywords` разделяйте значения точкой с запятой `;`. Например: `матан; мат анализ`.

Не меняйте `object_key`, `course_id`, `course_title`, `type`, `path`, `name` и `source_status`: эти поля обновляет `npm run search:sync`. Пустые `aliases`, `keywords` и `notes`, приоритет `0`, `enabled=TRUE` и `inherit=TRUE` для папки (`FALSE` для файла) — нормальное начальное состояние.

Пример заполнения (это только пример, реальные строки таблицы оставлены без придуманных тегов):

| name | aliases | keywords | priority |
| --- | --- | --- | ---: |
| Электротехника | элтех; эл тех | кирхгоф; цепи; амперметр; вольтметр | 20 |
| Математический анализ | матан; мат анализ | пределы; производные; интегралы | 20 |

## Рекомендуемый Excel workbook

`npm run search:workbook` обновляет очередь и создаёт `data/search/tagging-queue.xlsx`; на macOS команда автоматически открывает книгу в Excel. Повторяйте команду перед новым сеансом разметки, чтобы получить актуальную книгу из CSV.

- Лист «Разметка» содержит только список предметных папок, расположенных непосредственно внутри семестров (сейчас 29), и два поля: «Теги» и «Преподаватель». Название папки включено в «Теги» автоматически.
- `object_key` скрыт и служит машинным ключом для безопасного сопоставления; не редактируйте его или другие машинные поля.
- Лист «Синонимы» содержит общие для всех папок синонимы.
- Лист «Инструкция» кратко объясняет значения колонок.
- После редактирования запустите только `npm run search:workbook:apply`: команда импортирует разрешённые ручные поля и синонимы в CSV, затем запускает проверки, сборку и coverage.

Workbook исключён из Git. Если нужно отредактировать данные без Excel, используйте описанный ниже расширенный CSV-процесс.

## Расширенный CSV-процесс

Для папок выполните `npm run search:tagging-queue`, отредактируйте `data/search/tagging-queue.csv` и примените изменения через `npm run search:apply-tags`. Для глобальных синонимов редактируйте `search-synonyms.csv`. Затем вручную запустите `npm run search:validate` и `npm run search:build`.

## Обновить и проверить таблицы

Для удобной разметки папок сформируйте очередь:

```bash
npm run search:tagging-queue
```

По умолчанию очередь содержит активные включённые папки, лежащие непосредственно внутри семестров (глубина 2: курс/семестр/папка предмета). Сами папки семестров и вложенные разделы в неё не входят. Чтобы добавить все активные включённые папки, выполните `npm run search:tagging-queue -- --all`. Столбец `status` показывает класс: `root` — глубина 0, `priority` — глубина 2, `later` — остальные уровни. Очередь включает служебные поля `object_key`, `course_id`, `course_title`, `type`, `path`, `name`, `depth`, `status` и `source_status`; не меняйте их. Редактируйте только `aliases`, `keywords`, `inherit`, `priority`, `enabled` и `notes`. Изменение `enabled` применяется в основной таблице; отключённые объекты не попадут в будущий индекс и не передадут свои теги дальше.

Если выключить папку через очередь, команда применения уберёт её из следующей очереди. Чтобы снова включить её, установите `enabled=TRUE` в `search-tags.csv`, затем проверьте изменения и заново сформируйте очередь. Отключённая папка не передаёт собственные теги; включённые потомки всё ещё могут наследовать теги других включённых предков выше по пути.

После сохранения очереди примените её изменения к основной таблице:

```bash
npm run search:apply-tags
```

Команда сверяет машинные поля очереди с основной таблицей по `object_key` и прекращает работу, если каталог изменился или строка была подменена. Исправьте ситуацию пересозданием очереди и переносом проверенных ручных значений. `search-tags.csv` остаётся основной таблицей и source of truth.

1. После изменений каталога запустите `npm run search:sync`. Заполненные вручную поля сохранятся у объектов с тем же ключом. Исчезнувшие строки останутся с `source_status=missing`.
2. Перед публикацией запустите `npm run search:validate`.
3. После заполнения тегов соберите индекс командой `npm run search:build`.

`search-synonyms.csv` — отдельная таблица глобальных соответствий для всех каталогов. Пользовательские поля: `term`, `synonyms`, `enabled`, `notes`. Последний машинный столбец `object_key` нужен Excel для безопасной привязки строк при сортировке и переименовании; его создаёт команда, вручную не меняйте. Старый CSV без этого столбца автоматически мигрирует при создании workbook. Например, для `term=базы данных` синонимами могут быть `бд; субд`. Таблица пока не содержит заданных владельцем синонимов.

При переносе или переименовании путь меняется и вместе с ним меняется `object_key`. Старые теги останутся в строке со статусом `missing`; проверьте предупреждение sync и перенесите их вручную, если это действительно тот же объект.
